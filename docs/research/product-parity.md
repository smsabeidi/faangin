# Product parity research: Cluely and InterviewCoder

Retrieved October 11, 2026. Audience: principal product, desktop, inference, platform, and quality engineers. Target order: macOS first, Windows second; mobile and web surfaces remain part of the full parity inventory. This is a requirements input, not a claim that Faangin currently implements these capabilities.

## Evidence standard and research boundary

Public official pages and support documentation were read through the web tool. Firecrawl was attempted but is not installed in this environment. Selected response extracts are retained under `.firecrawl/`; those are research working files, excluded from source control. Public InterviewCoder help navigation, a demonstration thumbnail, and preparation-directory controls were also inspected in a browser.

- **Documented:** an official guide describes the workflow. This is stronger than a headline, but still does not establish native operation.
- **Claimed:** marketing or a changelog asserts a capability; executable behavior remains untested.
- **Observed web:** a public page, control, navigation outcome, or demonstration image was inspected directly. This verifies that public surface only.
- **Unknown:** not established from accessible official material. Unknown does not mean absent.

No account was created, paid plan purchased, executable downloaded, application installed, permission granted, or private API called. Screenshots, audio routing, model quality, latency, cloud persistence, account entitlements, and native visibility behavior therefore have no hands-on verification. An exact clone of two evolving products also requires a versioned behavioral baseline; a website review cannot certify 100% operational parity.

## Product interpretations

Cluely currently presents a meeting companion: desktop listening, on-demand assistance, transcripts, notes, and iPhone access. Its homepage advertises 300 ms transcription, 95% accuracy, and broad invisibility. Those numbers are vendor claims without a published test corpus or measurement definition in the inspected material. [Cluely homepage](https://cluely.com/)

InterviewCoder centers on technical interview assistance, expanding into behavioral and system-design prompts and a preparation website. Its public offering includes free application exploration, a $299 monthly plan with 1,000 credits, and $799 lifetime access; using AI requires payment. The advertised universal invisibility and success figures are unverified vendor claims. [InterviewCoder homepage and pricing](https://www.interviewcoder.co/)

The intended Faangin is the union of the two products' established workflows, with separate meeting and interview modes. Shared concepts should use one capture, transcript, context, response, history, and settings foundation. Distinct controls or timing must be preserved where they affect user behavior; visual similarity alone does not establish parity.

## Control baseline for interaction specifications

Cluely documents Cmd/Ctrl+Enter for assistance, Cmd/Ctrl+R for context reset, Cmd/Ctrl+backslash for widget hide/show, Shift+backslash for session start/stop, arrows for movement, and Shift+up/down for response scrolling. Controls can be remapped or disabled. Hiding the widget does not change capture protection. [Settings guide](https://support.cluely.com/en/articles/12418681-how-to-use-cluely-s-settings)

InterviewCoder documents Cmd+B visibility and Cmd+arrows movement. The public demonstration thumbnail depicts Cmd+H screenshot and Cmd+G start over; current bindings, Windows equivalents, scrolling/opacity commands, solve/debug submission, and shortcut defaults must be confirmed in the installed build. [Technical explanation](https://www.interviewcoder.co/still_working), [public demo](https://www.interviewcoder.co/help)

## Conflicts that constrain exactness

1. Cluely's older dashboard article says protection is enabled by default; newer dedicated support requires explicit activation. Homepage language omits the paid tier and app-specific limitations. Use separate requested state, entitlement state, and tested capture outcome. [Dashboard](https://support.cluely.com/en/articles/12101340-how-to-use-cluely-s-dashboard-app), [activation](https://support.cluely.com/en/articles/11989293-how-to-enable-undetectability)
2. Cluely download requirements permit Catalina/Intel, while support requires Ventura and inconsistent hardware-year restrictions. Windows ARM is mentioned in support but the download page says x64. These are distinct launch/install/capture compatibility questions. [Download](https://cluely.com/download), [requirements](https://support.cluely.com/en/articles/11628643-what-are-the-system-requirements)
3. The Cluely homepage's broad language coverage differs from the explicit input/output split. A translation setting must never imply unsupported audio recognition. [Languages](https://support.cluely.com/en/articles/12027152-how-to-change-languages)
4. InterviewCoder pricing/changelog and build catalog describe different plans/versions. Some pages promise blanket invisibility while help prescribes capture filtering. Public claims are not test results. [Changelog](https://www.interviewcoder.co/dashboard/changelog), [build catalog](https://www.interviewcoder.co/dashboard/previous-versions), [Zoom help](https://www.interviewcoder.co/help?section=shows-when-sharing)
5. The supported-app Cluely article simultaneously asserts advanced concealment, records conferencing exceptions, and says evasion is not intentionally implemented/tested. Record each as vendor language; do not derive a coherent internal architecture from it. [Supported apps](https://support.cluely.com/en/articles/12364416-what-apps-are-supported-for-undetectability)

## Acceptance protocol and unresolved discovery

The following are proposed Faangin gates, not competitor performance observations. For each supported platform, record OS/hardware, app build, capture API, permission state, display arrangement, conferencing app/version, and relevant capture mode. A feature is complete only when its success path, denied-permission path, cancellation path, offline path, and persistence behavior meet the signed specification.

Before implementation claims exactness, obtain an authorized native behavioral walkthrough for both products: clean-install onboarding; account/native handoff; audio devices and source selection; question capture and screenshot queue; solve/debug actions; complete shortcuts; model and language selectors; transcript correction; notes editing/sharing/revocation; resume/doc import; pricing enforcement; deletion; updater and migration; plus mobile and authenticated web workflows. Save versioned screenshots and input/output traces with personal data removed. Public demos can inform UI layout but cannot replace this test inventory.

| Gap | Why it matters | Required evidence or decision |
|---|---|---|
| Native baseline/build versions | Current public guides mix UI generations | Authorized clean install and version capture on macOS; independently repeat Windows. |
| Models/provider policies | “Latest” and “fine-tuned” do not reveal implementation | Current in-app roster, mode routing, regional availability, limits; choose Faangin providers independently. |
| Screenshot batching/solve/debug | Single screenshots and repeat captures are established; batch mechanics are not | Inspect queue maximum, ordering, crop/multi-monitor rules, solve trigger, retry/cancel/reset. |
| Audio/STT specifics | Latency and accuracy headlines lack definitions | Provider and stream behavior, sample rate, chunking, diarization, silence/end detection, reconnection, benchmark protocol. |
| Notes/memory/retrieval | Scope, citations, retention, and deletion propagation unknown | Multi-session query fixtures, shared-link permissions/revocation, retention settings, storage and sync behavior. |
| Prompt/profile/schema | Uploaded resume claims do not establish parsing/retrieval | File limits/formats, extraction errors, profile switches, template layout, grounding and deletion. |
| Billing/quotas | Desktop free counts and credit consumption unknown | Authenticated plan state, consumption schedule, daily reset basis, cancellation/refund/legacy rules. |
| Mobile current behavior | Guide describes v1 restrictions | Current iPhone baseline, microphone/background transitions, sync, entitlement sharing; explicitly decide mobile release gate. |
| Business/collaboration | Sharing does not establish a team product | Verify workspaces/roles/seats/SSO and integrations; retain unresolved surfaces in backlog. |
| Web prep/analytics/affiliates | Public controls do not establish full operation | Detail access, account limits, original/licensed corpus, compensation data source, dashboard analytics and referral attribution. |
| Visual/operational fidelity | No complete screenshot set exists | Per-screen state inventory with viewport, typography, responsive and accessibility targets. Use original branding and licensed assets. |

## Engineering handoff

The desktop lead owns permissions, audio/screen capture, overlay and shortcut behavior. The inference lead owns context snapshots, transcription stability, streaming and grounding. The platform lead owns auth, file parsing, history/sync, entitlements, updates and shared links. The product/UI lead owns dashboard, profiles, notes, interview actions and state coverage. Quality owns executable coding fixtures, audio corpora, native compatibility, and release evidence. Mobile and web preparation tracks remain visible obligations for full public-surface coverage.

Research status: public scope mapped; authenticated and native parity unverified. A first implementation may satisfy a defined desktop slice. It must not label remaining mobile, web, enterprise, concealment, model-quality, or billing gaps as completed.
