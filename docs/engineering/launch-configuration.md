## Public desktop configuration

The default public configuration is `config/cloud.supabase.json`. Override its path with `FAANGIN_CLOUD_CONFIG_FILE` when building another environment. The build accepts these fields:

| Field | Source |
| --- | --- |
| `supabaseUrl` | The selected project's API URL, `https://uxgphdpcgcpgwbwfibkx.supabase.co` |
| `publishableKey` | Supabase Dashboard → Project settings → API keys → active publishable key |
| `gatewayBase` | The same API origin followed by `/functions/v1/faangin-gateway`; derived when omitted |
| `licensePublicKeys` | Base64 SPKI Ed25519 public key(s) matching the environment's backend signing key |

Only these public values ship in the desktop. Secret/service-role keys, management tokens, provider/Stripe keys, refresh tokens, and the private signing key must never enter this JSON. The release parser rejects private/unknown fields, local origins, another project's gateway, and malformed verification keys. The matching signing key is deployed and remote licenses verify against this configuration. Private values stay in ignored owner-only files; the allowlist secret uploader excludes management credentials from Edge.

```sh
FAANGIN_CLOUD_CONFIG_FILE=/absolute/path/to/cloud.supabase.json npm run check:launch
FAANGIN_CLOUD_CONFIG_FILE=/absolute/path/to/cloud.supabase.json npm run verify:launch
```

Packaged apps ignore runtime endpoint overrides. Disposable desktop smoke profiles disable cloud access explicitly. Ordinary development builds use the selected project by default. Public metadata validation establishes configuration shape, not remote service health.
